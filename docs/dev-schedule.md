# 開発スケジュールと想定課題（学生向け）

## 想定スケジュール（2〜3週間）

### 1週目: 仕様確定と基盤構築
- 画面要件（入力/履歴/検索/設定/締切）を確定
- データ構造を決める（JSON/BIN/CSV）
- WPF + MVVM の雛形を作る
- `SettingsService` / `HistoryService` / `ScanFileService` を先に実装

### 2週目: 機能実装と結合
- 入力バリデーションと履歴追加
- 検索/削除/退避フロー
- CSV/BIN出力
- 締切表示とファイル監視

### 3週目: 仕上げ
- UI調整、操作フロー整理
- データ破損/例外時の挙動確認
- 配布手順の整理

## 想定される問題点

### 入力・重複
- 下5桁で重複判定する仕様を忘れる
- 10桁入力時の末尾5桁切り出しミス

### ファイルI/O
- `history.json` と `ids_*.bin` の同期がずれる
- 書き込み中に読み込みが走ると例外が出る
- `ids_*.bin` が壊れた時の扱いが未定

### 締切機能
- `time.json` の形式が揺れる（JSON/テキスト混在）
- ローカル時間の扱いが不一致

### UI/UX
- 既存データ検出時の分岐が曖昧
- 退避後の履歴リセットを忘れる

### 暗号化運用
- `students.enc` がない状態での動作確認不足
- ビルド時埋め込み方式を理解していない

## 引っ掛かりやすいポイント（注意）

- **保存基準パス**: `AppDomain.CurrentDomain.BaseDirectory`。実行フォルダ配下に `data/` と `scans/` がある前提。
- **履歴は全場所共通**: 表示は場所でフィルタされるが保存は1本。
- **退避はbinファイルのリネーム**: `ids_<場所>_<suffix>.bin` に変更。
- **`students.passphrase` は配布不要**: ビルド時に埋め込まれる。
- **UIでの警告**: 既存BINがある場合に必ず確認を出す。
